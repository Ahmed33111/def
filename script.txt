1. VUE D'ENSEMBLE DU PROJET
================================================================================

Ce projet est un systeme bancaire complet full-stack multi-rôles permettant la
gestion d'agences bancaires avec des opérations de comptes, transferts, cartes
bancaires, et un tableau de bord analytique avancé style Power BI.

Le systeme supporte 4 rôles :
  - ADMIN       : Gestion globale de toutes les agences et utilisateurs
  - DIRECTOR    : Gestion d'une agence spécifique (statistiques, clients, staff)
  - CASHIER     : Opérations courantes (création comptes, dépots, retraits, cartes)
  - USER/CLIENT : Consultation de comptes, transferts, cartes personnelles

4. BASE DE DONNEES (MySQL - banque)
================================================================================

Tables principales :

  agencies          : Agences bancaires (code, nom, adresse, directeur)
  users             : Utilisateurs (username, password BCrypt, role, agency_id)
  account           : Comptes bancaires (numéro, solde, user_id, statut)
  transactions      : Transactions (montant, type DEBIT/CREDIT, date, account_id)
  bank_cards        : Cartes (numéro, type VISA/MASTERCARD, limites, CVV, blocage)
  expense_category  : Catégories de dépenses (nom, couleur)
  virement_programme: Virements programmés (source, destination, montant, date)
  cashier_logs      : Journal d'audit caissier (type, description, statut)
  client_documents  : Documents clients (type, fichier, statut PENDING/APPROVED)

Relations clés :
  - users.agency_id        -> agencies.id
  - account.user_id        -> users.id
  - transactions.account_id -> account.id
  - bank_cards.account_id  -> account.id
  - cashier_logs.cashier_id -> users.id
  - client_documents.user_id -> users.id

5. SECURITE ET AUTHENTIFICATION
================================================================================

Mode d'authentification : HTTP Basic Authentication

Flux :
  1. Le client envoie ses identifiants en Base64 dans le header Authorization
  2. Le backend décode et vérifie username + password (BCrypt) via UserService.authenticate()
  3. Le rôle est vérifié via des validateurs dédiés :
     - validateUser(authHeader)     -> Retourne le user authentifié
     - validateCashier(authHeader)  -> Authentifie + vérifie ROLE_CASHIER
     - validateAdmin(authHeader)    -> Authentifie + vérifie ROLE_ADMIN
     - validateDirector(authHeader) -> Authentifie + vérifie ROLE_DIRECTOR
  4. En cas d'échec :
     - Identifiants invalides -> UnauthorizedException (401)
     - Rôle insuffisant       -> ForbiddenException (403)
  5. Le GlobalExceptionHandler convertit ces exceptions en réponses HTTP propres

Sécurité frontend :
  - Les identifiants sont stockés dans localStorage ('credentials')
  - Chaque requête fetch inclut le header Authorization
  - En cas de 401/403, la fonction handleAuthFailure() force la déconnexion
    et redirige vers la page de login (évite les dashboards "zombie")

7. FRONTEND - COMPOSANTS ET FONCTIONNEMENT
================================================================================

ROUTING (App.tsx) :
  - Non authentifié  -> LoginComponent
  - ROLE_ADMIN       -> AdminDashboard
  - ROLE_DIRECTOR    -> DirectorDashboard (avec sous-vues)
  - ROLE_CASHIER     -> CashierDashboard
  - ROLE_USER        -> AccountComponent

DASHBOARDS POWER BI STYLE :
  Chaque dashboard inclut :
  - KPI Cards animés (compteur animé avec easeOutCubic, durée 1200ms)
  - Graphiques d'évolution (AreaChart Recharts / LineChart Chart.js)
  - Graphiques en camembert (PieChart pour répartition types de comptes/cartes)
  - Graphiques en barres (comparaison agences, activité mensuelle)
  - Heatmap d'activité (tableau coloré avec intensité proportionnelle)
  - Filtres de période interactifs (semaine/mois/trimestre/année)
  - Données fetchées depuis /api/stats/dashboard?period=X

BIBLIOTHEQUES UTILISEES :
  - Recharts        : Graphiques Area, Pie, Bar dans Admin/Director/Cashier dashboards
  - Chart.js (react-chartjs-2) : Graphiques Line, Pie, Bar dans AccountComponent
  - Framer Motion   : Animations UI
  - Lucide React    : Icones
  - Tailwind CSS    : Styling utility-first
  - jsPDF           : Export PDF de relevés
  - SockJS + STOMP  : WebSocket pour notifications temps réel
  - ZXCVBN          : Vérification force du mot de passe

GESTION DES ERREURS :
  - handleAuthFailure(response) : Détecte 401/403 et appelle onLogout()
  - onLogout() : Supprime localStorage.credentials et redirige vers login
  - Notifications toast pour les erreurs métier

8. ML SERVICE - CLASSIFICATION DE DOCUMENTS
================================================================================

Le service ML (FastAPI, port 8000) classifie les documents uploadés par les clients.

Fonctionnement :
  1. Le client upload un document (image/PDF) via le frontend
  2. Le backend Spring Boot reçoit le fichier et l'appelle le ML service
  3. Le ML service analyse le nom de fichier et le contenu textuel
  4. Classification par mots-clés dans ces catégories :
     - KYC (pièce d'identité)
     - DEPOSIT_PROOF (justificatif de depot)
     - INCOME_PROOF (justificatif de revenu)
     - ADDRESS_PROOF (justificatif de domicile)
     - OTHER
  5. Retourne : type détecté + score de confiance + mots-clés trouvés

Fichiers :
  - main.py       : API FastAPI avec endpoints /classify et /health
  - classifier.py : Classifieur basé sur mots-clés (pas de modèle ML lourd)

11. FONCTIONNALITES PRINCIPALES
================================================================================

POUR LE CLIENT (USER) :
  - Consulter ses comptes et soldes
  - Voir l'historique des transactions
  - Effectuer des transferts (immédiats et programmés)
  - Gérer ses cartes bancaires (bloquer, paramètres)
  - Uploader des documents KYC
  - Voir ses statistiques personnelles (dashboard avec graphiques)
  - Exporter ses relevés en PDF

POUR LE CAISSIER :
  - Créer des comptes clients
  - Créer et gérer des cartes bancaires
  - Effectuer des depots et retraits
  - Clôturer des comptes
  - Voir les transactions de son agence
  - Consulter le journal d'audit
  - Dashboard avec KPIs, graphiques et heatmap

POUR LE DIRECTEUR :
  - Voir les statistiques de son agence
  - Gérer les clients et le staff
  - Comparer les performances entre agences
  - Dashboard avec évolution, camemberts, heatmaps

POUR L'ADMINISTRATEUR :
  - Gestion globale de toutes les agences
  - Gestion des rôles utilisateurs
  - Statistiques bancaires globales
  - Dashboard comparatif toutes agences

GESTION DOCUMENTAIRE :
  - Upload de documents par les clients
  - Classification automatique par le ML service
  - Revue et validation par le staff (caissier/admin/directeur)
  - Statut : PENDING -> APPROVED / REJECTED
